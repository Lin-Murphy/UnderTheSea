# opt 分支优化记录(2026-11-06)

分支:Unity Version Control `/main/opt`(从 `/main` cs:15 拉出)。**所有改动都只在这个工作区里,尚未 check in,也没有动其它分支。**
体验流程、美术、音效、配音时机都保持不变;改的是性能、稳定性和助手操作的安全性。

## 1. AprilTag 检测(场景3 探头)

| 问题 | 改动 |
|---|---|
| 检测在主线程同步跑(灰度转换 + 四边形检测 + 位姿估计),10 Hz 时每 0.1 秒卡住一帧渲染;VR 里周期性掉帧会让人不舒服 | 检测挪到后台 `Task`:主线程只拷贝一帧图像(约 1 ms)。内嵌包 `jp.keijiro.apriltag` 新增 `TagDetector.ProcessImageThreadSafe`(不经过 Unity Job System,可在任意线程调用)和可指定检测线程数的构造函数(默认 2,不跟渲染线程抢核心)。`runOnWorkerThread` 可关回同步模式 |
| 单帧误检会让海草 / 小丑鱼瞬间跳到别处 | 汉明距离 > 2、决策裕度 < 8、离头显 > 1.8 m 的检测直接丢弃;和当前位置相差 > 0.25 m 的"跳变"要连续两次一致才接受 |
| 原始位姿有抖动(10 Hz、2 倍降采样) | 位置用 One Euro 滤波(静止时去抖,快速移动时延迟很小;实测 10 Hz 下静止抖动 −45%,0.5 m/s 移动时滞后约 16 mm),旋转同比例 Slerp |
| — | 调试信息:`Status` 显示检测耗时,`RejectedDetections` 统计被过滤的次数 |

自检:`UnderTheSea > AprilTag > Self Test (synthetic frame)` 现在同时测后台线程路径(结果与原路径一致:ID 1、深度 0.1389 m)。

## 2. 助手手柄(右手柄)

| 问题 | 改动 |
|---|---|
| A 键手抖连按会直接跳过一整个场景 | `ExperienceController.RequestNext()`:进入新阶段 0.8 秒内再按 A 不生效(`advanceCooldown`)。空格、点击 Start 也走同一逻辑;过渡阶段的自动前进不受影响 |
| B 键一碰就重置,检查中误触会把孩子直接拉回现实 | 右手柄 B 改为**按住 0.6 秒**才回到 Start(`resetHoldSeconds`,填 0 恢复一按即重置)。键盘 B / R 仍是一按即重置 |
| 助手看不到头显画面,不知道按键有没有生效 | 手柄震动反馈:A 生效 = 一次短震(冷却中被忽略则不震);B 重置 = 两次短震;场景4 吸气到最大 = 一次轻震,提示"吸满了"。`hapticStrength` 可调,0 = 关闭 |

## 3. Quest 性能

- 新组件 `QuestPerformance`(Builder 自动挂在 Experience 上,只在真机生效):固定注视点渲染 Medium + 动态、CPU/GPU 档位 SustainedHigh、刷新率保持系统默认(可填 90/120)。启动时 logcat 打印一行 `[QuestPerformance] …` 方便确认。
- `SoftSeaweedStrands`:缓存组件(原来每帧 `GetComponent` 两次);每个节点的 `Pow / Sin / AngleAxis` 常量预先算好;Verlet 改为时间修正 + 阻尼按 72 Hz 换算 —— 头显上(72 Hz)手感不变,编辑器 / 其它刷新率下表现一致(实测 45/72/120 Hz 贴身比例 0.20/0.20/0.21)。
- `OceanStageView`:VR 显现程度不变时(完全沉浸的绝大部分时间)不再每帧重设几百个环境物体的缩放;水下根节点只在状态变化时 `SetActive`。
- `ReefArtDriver.ApplyLighting`:天色不变时不重复写全局 shader 参数和环境光;相机组件缓存,清屏方式 / 后处理只在沉浸状态变化时切换。
- `ReefFishSchool`:水下世界隐藏时(Standby 等下一位患者)不做逐条鱼的计算,重新显现时直接回到轨道。
- `StartButton`:只在悬停状态变化时改材质颜色;真机上不再做无意义的鼠标射线检测。

## 3b. 鱼绕珊瑚礁"掉帧"(第二轮)

原因有两层:
1. **整体帧率不够**。场景里在渲染的三角面约 220 万(珊瑚 157 万、水母 28 万、海葵 19 万、鱼 26 万),远超 Quest 3 每帧建议的 75–100 万。
   掉帧时系统的时间扭曲会补偿静止的景物,所以只有**移动的鱼**看起来一顿一顿的。
2. **鱼本身运动太快 / 有跳变**。近处鱼外圈绕得太快(线速度最高约 3.6 m/s,离眼睛 2–4 m,每帧跳 5 cm);
   躲藏结束游回轨道时用的是指数追赶,最后差 8 cm 时直接"吸"到轨道上(位置和朝向都跳一下)。

改动:

| 改动 | 结果(编辑器实测) |
|---|---|
| 每条鱼的 3 个纯色子网格合并成 1 个网格 + 1 个材质(颜色和光滑度写进 4×1 色板,Lit 光照不变)。`BuildReefMainScene.MergedFish` | 鱼的绘制次数 363 → 121;同机位逐像素对比平均差 0.24/255、最大 2/255,alpha 全为 1(Passthrough 不受影响) |
| 网格 LOD(Unity 6 Mesh LOD):珊瑚 / 海葵 / 水母在 `CollabArtSwap.Bake` 里自动生成,鱼在合并时生成;每级约减半 | 珊瑚 47968 → 24562 → 15576 …;鱼 2144 → 1088 → 576 … |
| `QualitySettings.meshLodThreshold` = 2(所有画质等级,Builder 写入) | 按 Quest 3 单眼 1832×1920、90° 视角,从患者机位:视野内面数降到原来的 **61%**,仅 0.08% 像素有可见差异(>16/255)。阈值 1 时为 70% |
| 近处鱼绕圈限速 `nearMaxSpeed` = 1.1 m/s | 最大线速度 3.6 → 1.12 m/s;从眼睛看最快 31°/s |
| 躲藏后游回轨道改为 smootherstep 混合(结束时位置、速度都正好等于轨道),`returnSpeed` = 1.4 m/s | 各阶段最大加速度 ≤ 16 m/s²(原来的 8 cm 跳变相当于约 400 m/s²) |
| 转身角速度上限 `maxTurnRate` = 300°/s | 原来掉头时一帧可转 15°(1075°/s) |

关于"复用鱼模型":所有鱼本来就共用同一个网格,复用只省内存,不减少绘制。GPU 实例化(120 条一次画完)评估后没有采用:
开着 SRP Batcher 时每次绘制的 CPU 开销本来就小,而一次画完就没法逐条剔除视野外的鱼、也用不了 LOD,GPU 顶点开销反而更大。
